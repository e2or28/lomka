# art/ — исходники спрайтов для стенда

Сюда кладутся PNG **как есть**, без импорта в редакторе. Стенд читает их
напрямую с диска: сохранил файл в графическом редакторе — нажал F5 в игре —
увидел. Открытый Godot для этого не нужен.

```bash
tools/run.sh        # запустить стенд
# F5  перечитать art/
# F1  сверка масштаба: спрайт рядом с силуэтом игрока, дверью и клеткой
```

## Что здесь лежит

| Файл | Что это |
|---|---|
| `player_body.png`, `player_arms.png`, `player_head.png` | Персонаж послойно, холст 128×192, порядок от заднего к переднему |
| `player.png` | Собранный персонаж целиком, для иконки и сверки |
| `player_layers.json` | Координаты и точки вращения слоёв |
| `player_side_stand.png`, `player_side_walk_1..6.png` | Ходьба в профиль с пустыми руками, холст 128×192 |
| `player_colt_stand.png`, `player_colt_walk_1..6.png` | То же с кольтом наизготовку: другой хват, поэтому свой набор |
| `colt.png` | Кольт в руке, 19×12. Ложится в кисть рукоятью — точка в `CharacterPose.WEAPON_GRIP` |
| `colt_top.png` | Кольт сверху, 19×4. Задел под лут на полу, пока не рисуется |
| `room_start.png` | Фон комнаты: пол 1160×640 плюс стены вокруг, всего 1370×850 |
| `monster.png` | **Заглушка**, собирается `tools/make_placeholder_art.py` |
| `folder.png` | Чёрный A4-портфель служащего, финальный снаряд 42×34 |

Стенд рисует персонажа слоями: корпус, руки, голова. Слои лежат на общем
холсте с общей системой координат, поэтому кладутся друг на друга без
подгонки. Якорь — `character_root` из json: это точка под ногами, а не
центр холста.

Послойная подача — правильный способ отдавать персонажа. Она даёт нативное
разрешение без потерь, прозрачность без полупрозрачных пикселей и задел на
анимацию: рука с точкой вращения — это уже бросок папки, а не новый спрайт.

## Набор кадров анимации

Кадры нельзя импортировать поштучно: обрезанные каждый по себе, они дают
персонажа, который дёргается на месте. Для них отдельный инструмент —
он приводит весь набор к одному росту и сажает на общий холст по двум
опорам, полу под ногами и центру туловища:

```bash
python3 tools/import_frames.py art/player_colt_walk ~/Downloads/кадры/*.png
```

Значения по умолчанию совпадают с уже стоящими кадрами: холст 128×192,
рост 156, пол на y=174. Новый набор обязан сесть в ту же посадку, иначе при
смене оружия персонаж прыгнет.

Своя ходьба нужна не всякому оружию, а тому, которое меняет хват. Оружие
без своего набора ходит базовым — см. `CharacterPose.walk_frame_names`.

## Комната

У комнаты важен не сам рисунок, а совпадение: нарисованный пол обязан лечь
ровно на ту область, внутри которой симуляция держит тела (`Room.bounds`).
Разъедется на десяток пикселей — персонаж упрётся в невидимую стену посреди
нарисованного пола.

```bash
python3 tools/import_room.py ~/Downloads/комната.png art/room_start.png \
    --inner 100,118,1400,888
```

Рамка пола задаётся руками и не угадывается кодом: граница пола и стены
размыта тенью, а текстура ковра и обоев одинаково зерниста — автоопределение
здесь врёт молча. Найти её проще всего по сетке:

```bash
ffmpeg -i комната.png -vf "drawgrid=w=100:h=100:t=2:c=red" -y /tmp/сетка.png
```

Инструмент печатает отступ стен — его надо перенести в `WorldView.ROOM_INSET`.
Тест «конвейер арта» краснеет, если картинка и константа разошлись.

## Картинка из чата или генератора

Если спрайт пришёл одной растянутой картинкой — холст 1024×1536, а рисунок
внутри вроде 47×127, — её надо привести к нативному размеру:

```bash
python3 tools/import_sprite.py ~/Downloads/картинка.jpeg art/monster.png
```

Инструмент сам находит шаг сетки апскейла, берёт по одному цвету на ячейку,
вырезает фон и счищает крошку JPEG по контуру. `--height N` ужимает,
`--step S` задаёт сетку вручную.

**Ужимать бывает нельзя.** Персонаж нарисован высотой 159 пикселей; на 64
у него теряется лицо, на 48 разваливается силуэт. Поэтому под спрайт
подогнан масштаб мира, а не наоборот: комната 1160×640, тело занимает
четверть её высоты.

## Заглушки

`monster.png` — не арт, а форма, без которой нельзя увидеть бой. Рисуется
кодом из пиксельной карты, чтобы её можно было править и чтобы никто не
принял её за решение. `folder.png` этим генератором больше не пересобирается:
там лежит утверждённый A4-портфель.

```bash
python3 tools/make_placeholder_art.py
```

Положи настоящий PNG с тем же именем — он их перекроет.

## Зачем именно так

Главный открытый вопрос проекта — рисует Егор сам или нужен художник
(`docs/DECISIONS.md`). Отвечает на него художественный тест на M1: три врага,
один предмет, кусок комнаты, два вечера. Сколько кругов «нарисовал —
посмотрел» уместится в эти два вечера, настолько честным будет ответ.
Обычный путь через импорт и перезапуск режет число кругов вдвое.

## Что тут не живёт

Готовые ассеты игры — в `assets/`, обычным импортом Godot. Этот каталог
помечен `.gdignore`: движок в него не заглядывает, `.import`-мусор не
плодится, в билд файлы не попадают. К M5, когда спрайтов станут сотни,
рабочий конвейер будет через `assets/`, а `art/` останется черновой.
