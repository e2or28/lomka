# art/ — исходники спрайтов для стенда

Сюда кладутся PNG **как есть**, без импорта в редакторе. Стенд читает их
напрямую с диска: сохранил файл в графическом редакторе — нажал F5 в игре —
увидел. Открытый Godot для этого не нужен.

```bash
tools/run.sh        # запустить стенд
# F5  перечитать art/
# F1  сверка масштаба: спрайт рядом с силуэтом игрока, дверью и клеткой
```

## Что здесь лежит

| Файл | Что это |
|---|---|
| `player_body.png`, `player_arms.png`, `player_head.png` | Персонаж послойно, холст 128×192. Стенд их **не читает**: анфас убран, см. ниже |
| `player.png` | Анфасная стойка. Она же идёт на иконку и на сверку масштаба |
| `player_layers.json` | Координаты и точки вращения слоёв |
| `player_side_stand.png`, `player_side_walk_1..6.png` | Ходьба в профиль с пустыми руками, холст 128×192 |
| `player_colt_stand.png`, `player_colt_walk_1..6.png` | То же с кольтом наизготовку: другой хват, поэтому свой набор |
| `colt.png` | Кольт в руке, 19×12. Ложится в кисть рукоятью — точка в `CharacterPose.WEAPON_GRIP` |
| `colt_top.png` | Кольт сверху, 19×4. Задел под лут на полу, пока не рисуется |
| `room_start.png` | Фон комнаты: пол 1186×604 плюс стены вокруг, всего 1370×880 |
| `monster.png` | **Заглушка**, собирается `tools/make_placeholder_art.py` |
| `folder.png` | Чёрный A4-портфель служащего, финальный снаряд 42×34 |
| `bullet.png` | **Заглушка**, 24×10. Снаряд кольта, летит носом вперёд |
| `player_colt_front.png` | Анфасная стойка с пистолетом. Пистолет накладывается сверху, как и в профиле |

Стенд рисует персонажа одним нарисованным кадром. На ходу это **всегда
профиль**: кадров ходьбы вверх и вниз в наборе нет. Разворачивается он на
остановке — лицом к зрителю, если последним шёл по вертикали, и тем боком,
которым шёл, если по горизонтали. Стрельба вбок разворачивает в профиль
и стоящего анфас.

Якорь — `character_root` из json: точка под ногами, а не центр холста.
Анфас и профиль сидят на нём одинаково, поэтому разворот не сдвигает
персонажа с места.

Сборка анфаса из слоёв убрана 4 сентября 2026. Она включалась только в
покое, и на каждой остановке тело разворачивалось к зрителю, а оружие
перескакивало с одной точки хвата на другую. Сами слои оставлены в
каталоге: разрешение у них нативное, а рука с точкой вращения — задел под
настоящий бросок.

## Канал Саши: Google Drive

Исходники приезжают из папки «игра саша егор» на Google Drive. Она **не**
источник для игры: там рисунки по два мегабайта, растянутые до 1536×1024,
а стенд читает спрайты в родном размере. Цепочка такая:

```
Drive  →  art/_inbox/  →  tools/import_*.py  →  art/*.png
         (мимо гита)      (в родной размер)     (в гите)
```

```bash
tools/pull_art.sh          # забрать текущее состояние Drive в art/_inbox/
```

Настройка один раз: `brew install rclone`, затем `rclone config` — новый
remote с именем `lomka`, storage `drive`, **scope 2 (read-only)**, остальное
по умолчанию. Read-only взят намеренно: скрипт физически не может ничего
записать или удалить в Drive.

Перезалитый файл с тем же именем скачивается заново — rclone сравнивает
размер и дату, идентификаторы файлов ему не нужны. Удалённое в Drive
в `art/_inbox/` остаётся: это копирование, а не зеркало. Каталог
одноразовый, удалить его можно в любой момент.

Что где лежит на Drive:

| Папка | Что в ней |
|---|---|
| `office_worker/` | Персонаж: слои, `layer_metadata.json` (это наш `player_layers.json`), `source_1024/`, `godot_256/`, `godot_128/` |
| `office_worker/ходьба вправо/` | Семь файлов: `1` — стойка, `2`–`7` — цикл ходьбы |
| `office_worker/с пистолетом(другим оружием)/` | Стойка с пистолетом плюс `пистолет 1`–`5` |
| `locations/start/` | Пять комнат стартовой локации: `центр` (наша), `верхняя`, `левая`, `правая`, `старт низ` |
| `оружия/` | Пока пусто |

### Ходьба: как принять новый набор

Цикл и стойка обязаны сесть в одну посадку, иначе персонаж дёрнется на
остановке. Поэтому оба набора гонятся одним инструментом с одними
значениями по умолчанию:

```bash
tools/pull_art.sh
cd art/_inbox/office_worker/ходьба\ вправо
python3 ../../../../tools/import_frames.py ../../../player_side_walk 2.png 3.png 4.png 5.png 6.png 7.png
python3 ../../../../tools/import_frames.py ../../../player_side_stand 1*.png
mv ../../../player_side_stand_1.png ../../../player_side_stand.png
```

Кадров в цикле должно остаться шесть: их число записано в
`CharacterPose.WALK_FRAMES`, и набор из пяти или семи потребует правки
константы, а не только файлов.

Проверка — F5 в стенде, затем `tools/test.sh`: тест «направление взгляда»
краснеет, если новый набор нарисован лицом влево.

## Набор кадров анимации

Кадры нельзя импортировать поштучно: обрезанные каждый по себе, они дают
персонажа, который дёргается на месте. Для них отдельный инструмент —
он приводит весь набор к одному росту и сажает на общий холст по двум
опорам, полу под ногами и центру туловища:

```bash
python3 tools/import_frames.py art/player_colt_walk ~/Downloads/кадры/*.png
```

Значения по умолчанию совпадают с уже стоящими кадрами: холст 128×192,
рост 156, пол на y=174. Новый набор обязан сесть в ту же посадку, иначе при
смене оружия персонаж прыгнет.

Своя ходьба нужна не всякому оружию, а тому, которое меняет хват. Оружие
без своего набора ходит базовым — см. `CharacterPose.walk_frame_names`.

## Комната

У комнаты важен не сам рисунок, а совпадение: нарисованный пол обязан лечь
ровно на ту область, внутри которой симуляция держит тела (`Room.bounds`).
Разъедется на десяток пикселей — персонаж упрётся в невидимую стену посреди
нарисованного пола.

```bash
python3 tools/import_room.py ~/Downloads/комната.png art/room_start.png \
    --inner 100,118,1400,888
```

Рамка пола задаётся руками и не угадывается кодом: граница пола и стены
размыта тенью, а текстура ковра и обоев одинаково зерниста — автоопределение
здесь врёт молча. Найти её проще всего по сетке:

```bash
ffmpeg -i комната.png -vf "drawgrid=w=100:h=100:t=2:c=red" -y /tmp/сетка.png
```

Тест «форма комнаты» краснеет, если картинка и константы разошлись.

### Три числа, которые обязаны сходиться

| Что | Где лежит | Сейчас |
|---|---|---|
| Отступ от края картинки до пола | `WorldView.ROOM_INSET` | 91, 180 |
| Игровая зона | `Room.dev_room().bounds` | 1186×604 |
| Дверные косяки | `Room.dev_room().blockers` | два по 35 пикселей |

Границы **не равны** нарисованному полу — почему, написано в
`../docs/DECISIONS.md`, «Комната подгоняется под персонажа». Коротко: сверху
тело стоит перед стеной и не должно выносить голову за картинку, снизу
заходит на стену, потому что стоит перед ней.

### Верхняя стена растянута кодом

Комната пришла нарисованной сверху: у верхней стены была видна её толщина
(60 пикселей), а не лицевая часть. Персонаж ростом 156 торчал над ней
целиком. До настоящего рисунка стена растянута механически — полоса обоев
под лампами размножена по вертикали, а пол поджат, чтобы всё осталось
в окне 1400×880:

```bash
ffmpeg -i было.png -filter_complex "\
[0]crop=1370:62:0:0[a];\
[0]crop=1370:16:0:62,scale=1370:96[b];\
[0]crop=1370:22:0:78[c];\
[0]crop=1370:638:0:100,scale=1370:588[d];\
[0]crop=1370:112:0:738[e];\
[a][b][c][d][e]vstack=5" -y art/room_start.png
```

Команда **не идемпотентна**: второй прогон растянет стену дважды. Она здесь
как запись того, что сделано, а не как шаг конвейера. Настоящая верхняя
стена — арт-задача на доске.

## Картинка из чата или генератора

Если спрайт пришёл одной растянутой картинкой — холст 1024×1536, а рисунок
внутри вроде 47×127, — её надо привести к нативному размеру:

```bash
python3 tools/import_sprite.py ~/Downloads/картинка.jpeg art/monster.png
```

Инструмент сам находит шаг сетки апскейла, берёт по одному цвету на ячейку,
вырезает фон и счищает крошку JPEG по контуру. `--height N` ужимает,
`--step S` задаёт сетку вручную.

**Ужимать бывает нельзя.** Персонаж нарисован высотой 156 пикселей; на 64
у него теряется лицо, на 48 разваливается силуэт. Поэтому под спрайт
подогнан масштаб мира, а не наоборот: пол комнаты 1186×604, тело занимает
четверть её высоты.

## Заглушки

`monster.png` — не арт, а форма, без которой нельзя увидеть бой. Рисуется
кодом из пиксельной карты, чтобы её можно было править и чтобы никто не
принял её за решение. `folder.png` этим генератором больше не пересобирается:
там лежит утверждённый A4-портфель.

```bash
python3 tools/make_placeholder_art.py
```

Положи настоящий PNG с тем же именем — он их перекроет.

## Зачем именно так

Главный открытый вопрос проекта — рисует Егор сам или нужен художник
(`docs/DECISIONS.md`). Отвечает на него художественный тест на M1: три врага,
один предмет, кусок комнаты, два вечера. Сколько кругов «нарисовал —
посмотрел» уместится в эти два вечера, настолько честным будет ответ.
Обычный путь через импорт и перезапуск режет число кругов вдвое.

## Что тут не живёт

Готовые ассеты игры — в `assets/`, обычным импортом Godot. Этот каталог
помечен `.gdignore`: движок в него не заглядывает, `.import`-мусор не
плодится, в билд файлы не попадают. К M5, когда спрайтов станут сотни,
рабочий конвейер будет через `assets/`, а `art/` останется черновой.
